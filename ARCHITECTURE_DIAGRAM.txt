PROCESSING PIPELINE
==================

PHASE 2: Entity Extraction (15-90 seconds)
──────────────────────────────────────────

User uploads PDF
     │
     ├─> PDFService extracts text + bounding boxes (PyMuPDF)
     │
     ├─> NLPService processes with InLegalBERT (sliding window)
     │   • 400 token chunks, 50 token overlap
     │   • Confidence scoring
     │
     └─> Bulk insert entities into database
         • ID, type, text, confidence, bbox, requires_review

Frontend polls every 2 seconds
     │
     └─> Displays entity table when ready


PHASE 3: Action Plan Generation (20-130 seconds)
────────────────────────────────────────────────

User clicks "Generate Action Plan"
     │
     ├─> Backend dispatches Celery task
     │
     ├─> FAISSRetrieverService retrieves 3 similar precedents
     │   • Uses all-MiniLM-L6-v2 embeddings
     │   • In-memory FAISS search
     │
     ├─> ActionPlanGenerator synthesizes context:
     │   • Entity summary (top 5 per type)
     │   • Historical precedents
     │
     ├─> Invokes Ollama (Llama 3.1 8B):
     │   • System prompt: Expert Indian legal strategist
     │   • Format: JSON output only
     │   • PydanticOutputParser ensures schema compliance
     │
     ├─> Stores result in Case.generated_action_plan (JSONB)
     │   • ComplianceAssessment
     │   • LitigationROI (with ₹ costs)
     │   • StatutoryTimeline
     │   • ActionDirectives (1-20 tasks)
     │
     └─> Frontend polls and displays action plan
         • 4 tabbed sections
         • Color-coded urgency
         • Financial analysis in INR


DOCKER ORCHESTRATION
====================

docker-compose.yml coordinates:

┌──────────────────────────────────────────────────────────────┐
│  postgres:16         Database (single source of truth)       │
│  redis:7             Cache + Celery broker                   │
│  ollama/ollama       Llama 3.1 8B inference engine           │
│  backend (FastAPI)   Main service orchestration              │
│  celery_worker       Async task processor (Phase 2 + 3)      │
│  frontend (Next.js)  User interface                          │
└──────────────────────────────────────────────────────────────┘

All services connected via internal network
Health checks ensure readiness before dependent services start


TECHNOLOGY STACK
================

Frontend:          Next.js 15 + React 19 + TypeScript + Tailwind CSS
Backend:           FastAPI 0.109 + SQLAlchemy 2.0 async
Database:          PostgreSQL 16
Cache/Queue:       Redis 7 + Celery 5.3
Phase 2 NLP:       PyMuPDF + pytesseract + law-ai/InLegalBERT
Phase 3 LLM:       LangChain + Ollama (Llama 3.1 8B) + FAISS
Embeddings:        sentence-transformers/all-MiniLM-L6-v2
DevOps:            Docker + Docker Compose
